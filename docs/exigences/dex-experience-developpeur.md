# Exigences — Expérience développeur (DEX)

Mode : **N** = natif Azure, **C** = configuration, **D** = développement spécifique. La version indique quand l'exigence devient obligatoire. Statut : `À faire`, `En cours`, `Fait`, `Abandonnée`.

| ID | Exigence | Version | Mode | Statut |
|---|---|---|---|---|
| DEX-01 | Un guide de démarrage et un exemple d'appel fonctionnel existent. | V1 | C | À faire |
| DEX-02 | Toute demande passe par le processus de qualification (`docs/gouvernance.md`). | V1 | C | À faire |
| DEX-03 | Un modèle d'agent et un modèle d'adaptateur sont fournis. | V2 | D | À faire |
| DEX-04 | Un bac à sable à budget plafonné accueille les expérimentations (N1). | V2 | C | À faire |
| DEX-05 | Des règles Azure empêchent la création de ressources IA hors plateforme et les types de déploiement non autorisés. | V2 | C | À faire |
| DEX-06 | Le délai de mise en service d'un cas d'usage standard est mesuré et a une cible. | V2 | C | À faire |
| DEX-07 | Un portail développeur publie la documentation des API et les catalogues. | V4 | C | À faire |

*Pourquoi ce bloc : la réutilisation n'arrive que si passer par la plateforme est plus simple que la contourner.*
