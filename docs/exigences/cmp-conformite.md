# Exigences — Conformité (CMP)

Mode : **N** = natif Azure, **C** = configuration, **D** = développement spécifique. La version indique quand l'exigence devient obligatoire. Statut : `À faire`, `En cours`, `Fait`, `Abandonnée`.

| ID | Exigence | Version | Mode | Statut |
|---|---|---|---|---|
| CMP-01 | Le traitement reste dans l'UE. Le type de déploiement est imposé par une règle Azure (ADR-03). | V1 | C | À faire |
| CMP-02 | Un registre recense les cas d'usage IA et leur classification de risque au regard du règlement européen sur l'IA. | V1 | C | À faire |
| CMP-03 | Chaque cas d'usage fait l'objet d'une analyse RGPD : finalité, base légale, durées de conservation. | V1 | C | À faire |
| CMP-04 | Les utilisateurs sont informés qu'ils interagissent avec une IA. | V1 | C | À faire |
| CMP-05 | Toute modification de production est traçable : qui, quoi, quand, quelle demande de changement. | V1 | C | À faire |
| CMP-06 | Le droit à l'effacement est outillé (voir STA-04). | V2 | C | À faire |
| CMP-07 | Les conditions d'utilisation d'un modèle sont analysées avant son ajout au catalogue. | V2 | C | À faire |
| CMP-08 | Une analyse d'impact précède tout cas d'usage manipulant des données sensibles. | V3 | C | À faire |
