# Critères de réussite globaux

La plateforme atteint son objectif lorsqu'on peut démontrer que :

| Critère | Atteint en |
|---|---|
| Un changement de modèle se fait sans modifier les clients utilisant un alias stable | V1 |
| Chaque appel est attribuable à un utilisateur et à une application | V1 |
| Les secrets ne sont jamais transmis aux consommateurs | V1 |
| Les policies sont composées de fragments réutilisables | V1 |
| Un environnement peut être reconstruit depuis le code | V1 |
| Les modifications de production sont auditables | V1 |
| Un modèle s'ajoute par une modification déclarative | V1 (base), V2 (chaîne complète) |
| Un nouveau canal utilise un agent existant sans recréer d'infrastructure | V2 |
| Power Platform et une application sur site appellent le même service | V2 |
| Une société est embarquée sans déploiement manuel de composants partagés | V2 |
| Quotas et budgets s'appliquent automatiquement | V2 |
| Les coûts sont visibles par société, projet et session | V2 |
| Les tests s'exécutent automatiquement | V1 (infrastructure), V2 (policies et agents) |
| Les décisions d'architecture sont traçables | V1 |
| Une autre personne peut reprendre le projet depuis la documentation | Vérifié à chaque version |
| Un agent ne restitue jamais un document inaccessible à son utilisateur | V3 |
| Un nouveau cas d'usage standard est mis en service en libre-service | V4 |
